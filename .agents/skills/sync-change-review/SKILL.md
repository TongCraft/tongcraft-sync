# Sync 改动审查

从改动及其调用关系寻找具体问题，给出触发条件、影响和证据。审查默认只读；用户已要求修复时，完成授权修复并复查受影响部分。

先读 [AGENTS.md](../../../AGENTS.md) 的代码地图与约束；测试范围与证据限制见 [本地检查指南](../../../docs/LOCAL_CHECKS.md)。命令在仓库根目录执行。

## 确定审查范围

查看分支与完整工作区，包括已暂存、未暂存和未跟踪文件：

```sh
git status --short --branch --untracked-files=all
git diff
git diff --cached
git ls-files --others --exclude-standard
```

用户指定 PR、分支或基准时，确认实际基准，阅读从该基准到当前提交的完整差异，再合并工作区中的相关改动。不要只用 `HEAD~1` 代替整个分支，也不要仅凭 `git diff` 为空就认定没有改动。单独读取相关未跟踪文件。

区分本次变更、原有问题与其他人的已有工作；只将有证据的问题归因于本次变更。定位调用方、消费者和测试后再判断影响，不因文件名相似就扩大审查范围。

## 按影响面检查

只展开与本次改动相关的项目：

| 影响面 | 重点问题与入口 |
| --- | --- |
| 客户端生命周期与网络 | `SyncClient.java`：主线程与工作线程交接、连接 generation、退出或切换后的迟到响应、WebSocket 重连与补偿刷新、缓存写入及哈希校验 |
| Litematica 与几何 | `LitematicaBridge.java`：原点、旋转、镜像、子区域偏移与启用状态、维度、移除和选择；共享投影是否泄漏到本地保存记录 |
| 公共与个人状态 | `Wire.java` 和相关客户端/服务处理：发布字段、公共名称、个人隐藏和别名、版本冲突；个人状态是否影响他人 |
| 认证、权限与文件 | 两个服务的处理路径及 `service/src/validation.js`：正版会话证明、邀请单次使用、成员停用、所有者权限、下载访问、资源限制和异常文件拒绝 |
| 协议与持久化 | Java 客户端、Node 与 Worker 消费方是否接受一致的字段和错误语义；已有数据重启后是否可读；测试模拟是否掩盖兼容性变化 |
| 游戏界面 | Screen 类的按钮条件、异步状态、错误显示和实际布局；查看本次截图，截图存在不等于布局正确 |
| 检查与配置 | profile 是否覆盖改动、失败/阻塞/零测试能否正确拒绝、产物是否来自对应构建、本地绑定是否仍为模拟资源；Skill 路由、相对链接及命令是否有效 |

不要用“源码包含某个关键字”证明线程、权限或几何正确。沿实际执行路径说明问题；必要时使用小型复现或对应的行为测试。单石块蓝图不能证明旋转、镜像和多子区域几何正确。

## 审查结论

优先报告影响正确性、兼容性、权限或交付结果的问题，给出文件和行号、触发条件、后果及复现/测试证据。按严重程度排序，区分已确认缺陷与待验证疑点。不要把纯风格偏好或未经验证的猜测写成必须修复的缺陷。

无发现时说明已审查范围和剩余验证缺口，不宣称没有潜在问题。只有实际运行过的检查才写成通过；已有测试没有覆盖改动时，指出需要什么场景才能验证。

本 Skill 不默认执行全量检查。实现后需要交付或准备提交时，转到 [sync-pre-submit](../sync-pre-submit/SKILL.md) 选择检查；修复后仍然有效的检查可以复用。
